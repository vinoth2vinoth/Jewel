# Design Plan: Jewel v0.9.0 Phase 3 - Isolated Sandbox Verification Runner

We will implement Phase 3 of the Jewel v0.9.0 roadmap: **Isolated Sandbox Verification Runner**. This allows running verification commands inside a sandboxed Docker container, providing isolation for execution, file access, and environment variables.

---

## 1. Affected Files

1. **`src/core/config.ts`**:
   - Add the following properties to `JewelConfig` interface:
     - `useSandbox?: boolean;`
     - `sandboxFallbackToHost?: boolean;`
     - `sandboxImage?: string;`
     - `sandboxVolumes?: Record<string, string>;`
     - `sandboxEnv?: Record<string, string>;`
   - Update `DEFAULT_CONFIG` with defaults:
     - `useSandbox: false`
     - `sandboxFallbackToHost: false`
     - `sandboxImage: 'node:18-slim'`
     - `sandboxVolumes: {}`
     - `sandboxEnv: {}`
   - Update `validateAndMergeConfig()`:
     - Validate `useSandbox` is a boolean.
     - Validate `sandboxFallbackToHost` is a boolean.
     - Validate `sandboxImage` is a string.
     - For `sandboxVolumes` and `sandboxEnv`, validate that they are plain objects (i.e. `typeof val === 'object' && val !== null && !Array.isArray(val)`) and that all keys and values are strings.
     - For `sandboxVolumes` values (container-side paths), validate that each starts with a forward slash (`/`), throwing a validation error if not.
     - Properly merge these options.

2. **`src/core/config.test.ts`**:
   - Add tests to verify validation and parsing of the new sandbox options:
     - Verify default values for sandbox options (especially that `sandboxFallbackToHost` defaults to `false` and `sandboxImage` defaults to `'node:18-slim'`).
     - Verify that correct values (e.g. `sandboxVolumes: { "./host": "/container" }`) pass validation.
     - Verify that invalid types (e.g. `useSandbox: "invalid"`, `sandboxVolumes: []`, or non-absolute container paths like `"container_path"`) throw validation errors.

3. **`src/verification/runner.ts`**:
   - Change `import { execSync } from 'child_process';` to `import * as cp from 'child_process';`.
   - Update the existing host execution call on line 93: replace `execSync(...)` with `cp.execSync(...)` to prevent ReferenceErrors.
   - Introduce an exported helper namespace `dockerUtils` to wrap Docker checks and executions, allowing clean method stubbing in unit tests without ESM read-only assignment issues:
     ```typescript
     export const dockerUtils = {
       isDockerAvailable(): boolean {
         try {
           cp.execSync('docker info', { stdio: 'ignore', timeout: 3000 });
           return true;
         } catch {
           return false;
         }
       },
       executeDocker(args: string[], cwd: string, env: Record<string, string | undefined>) {
         return cp.spawnSync('docker', args, { cwd, stdio: 'pipe', encoding: 'utf8', env });
       }
     };
     ```
   - Update `runVerification(config, cwd)`:
     - Check Docker availability **exactly once** before entering the loop:
       ```typescript
       const dockerAvailable = config.useSandbox ? dockerUtils.isDockerAvailable() : false;
       ```
     - For each command execution inside the loop:
       - If `config.useSandbox` is true:
         - If Docker is NOT available:
           - Check `config.sandboxFallbackToHost`:
             - If `config.sandboxFallbackToHost` is `true`:
               - Fall back to normal host execution using `cp.execSync`.
               - Prepend `"Sandbox verification: Docker not available or daemon is not running. Falling back to host execution.\n"` to the resulting `stderr` field of the command results.
             - If `config.sandboxFallbackToHost` is `false` (default):
               - Block host execution to prevent silent sandbox escape.
               - Record the command result with `status: 'FAIL'`, `exitCode: 1`, and `stderr: "Sandbox verification failed: Docker is not available or daemon is not running, and sandboxFallbackToHost is disabled."`.
         - If Docker IS available:
           - Construct `dockerArgs` as an array of strings to run via `dockerUtils.executeDocker(dockerArgs, cwd, execEnv)`. Calling `spawnSync` under the hood without shell execution prevents host-shell escaping issues and Windows Git Bash path corruption.
           - Normalize all host paths passed to `-v` (for `cwd`, the `dist` directory, and custom volume mappings from `sandboxVolumes`) using `.replace(/\\/g, '/')` to prevent backslash syntax errors on Windows hosts.
           - Populate `dockerArgs`:
             - `run`, `--rm`, `-i`
             - `-v`, `${path.resolve(cwd).replace(/\\/g, '/')}:/workspace`
             - `-w`, `/workspace`
           - Handle host permission locking on Linux/Unix platforms: if `process.getuid` and `process.getgid` are defined, append `--user`, `${process.getuid()}:${process.getgid()}` to `dockerArgs`.
           - Set `HOME=/tmp` inside the container: pass `-e`, `HOME` to `dockerArgs`, and assign `execEnv.HOME = '/tmp'` on the host environment object. This prevents node/npm crashes caused by permission issues on the default root home directory in Unix containers running under non-root `--user`.
           - Mount Jewel's `dist` directory: parent of the compiled runner.js (`path.resolve(__dirname, '..')`) normalized and mapped to `/opt/jewel/dist` in the container. Add `-v`, `${path.resolve(__dirname, '..').replace(/\\/g, '/')}:/opt/jewel/dist`.
           - To protect secrets, environment variables are NOT passed via command line arguments using `-e KEY=VALUE` (which is visible in host process tables). Instead, we pass them via `spawnSync`'s `env` options, and tell Docker to export them into the container using `-e KEY`:
             ```typescript
             const execEnv = { ...process.env, HOME: '/tmp' };
             ```
           - Pass process auditing configuration if `config.auditSpawnedProcesses` is enabled:
             - Add `-e`, `JEWEL_AUDIT_CONFIG` and `-e`, `NODE_OPTIONS` to `dockerArgs`.
             - Add the values to the host child process environment `execEnv`:
               - `execEnv.JEWEL_AUDIT_CONFIG = JSON.stringify(auditConfig)`
               - `execEnv.NODE_OPTIONS = '--require /opt/jewel/dist/verification/preload.js'`
           - Pass custom volume mappings from `config.sandboxVolumes` (resolving relative host paths relative to `cwd` and normalizing backslashes):
             ```typescript
             if (config.sandboxVolumes) {
               for (const [host, container] of Object.entries(config.sandboxVolumes)) {
                 const absHost = path.resolve(cwd, host).replace(/\\/g, '/');
                 dockerArgs.push('-v', `${absHost}:${container}`);
               }
             }
             ```
           - Pass custom environment variables from `config.sandboxEnv` with support for host environment variable resolution to avoid committing secrets:
             ```typescript
             if (config.sandboxEnv) {
               for (const [key, val] of Object.entries(config.sandboxEnv)) {
                 let resolvedVal = val;
                 if (val.startsWith('$')) {
                   const hostEnvName = val.slice(1);
                   resolvedVal = process.env[hostEnvName] || '';
                 }
                 execEnv[key] = resolvedVal;
                 dockerArgs.push('-e', key);
               }
             }
             ```
           - Append the image name (`config.sandboxImage || 'node:18-slim'`).
           - Append shell execution wrapping: `['sh', '-c', cmdLine]`.
           - Execute: `const spawnResult = dockerUtils.executeDocker(dockerArgs, cwd, execEnv);`
           - Parse and handle exit code and errors cleanly:
             ```typescript
             let exitCode = spawnResult.status;
             let stdout = spawnResult.stdout || '';
             let stderr = spawnResult.stderr || '';
             if (exitCode === null || exitCode === undefined) {
               exitCode = 1;
               let errMsg = '';
               if (spawnResult.error) {
                 errMsg = spawnResult.error.message;
               } else if (spawnResult.signal) {
                 errMsg = `Docker process terminated by signal: ${spawnResult.signal}`;
               } else {
                 errMsg = 'Unknown failure starting docker.';
               }
               stderr += (stderr ? '\n' : '') + `Docker execution error: ${errMsg}`;
             }
             ```

## 2. Host Environment Variable Isolation Note

Since the container runs in an isolated environment, it will not inherit host environment variables (like `PATH` or custom API keys) unless explicitly mapped in `sandboxEnv`. This is normal and expected container behavior, and will be noted in config documentation/comments.
