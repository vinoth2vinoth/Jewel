# Design Plan: Jewel v0.10.0 Phase 1 - Semantic Symbol Isolation Guard

Implement public/exported symbol changes check and validation using task contract and config `allowedSymbolChanges` parameters.

## 1. Affected Files
1. **`src/core/config.ts`**:
   - Add `allowedSymbolChanges?: string[]` to `JewelConfig` interface.
   - Add `allowedSymbolChanges: []` to `DEFAULT_CONFIG`.
   - Update `validateAndMergeConfig` to support and validate `allowedSymbolChanges` (must be an array of strings).
2. **`src/core/config.test.ts`**:
   - Add unit tests verifying config parsing, merging, and validation of `allowedSymbolChanges`.
3. **`src/core/session.ts`**:
   - Add `allowedSymbolChanges?: string[]` to `TaskContract` interface.
4. **`src/agents/structured-schema.ts`**:
   - Add `allowedSymbolChanges` to `TaskContractSchema` properties.
5. **`src/agents/json-response.ts`**:
   - Validate `allowedSymbolChanges` string array in `validateTaskContractJson`.
6. **`src/agents/json-response.test.ts`**:
   - Add unit tests verifying contract validation flags invalid formats of `allowedSymbolChanges`.
7. **`src/safety/diff-guard.ts`**:
   - Update `runDiffGuard` and `runASTDiffAnalysis` to receive `allowedSymbolChanges: string[] = []`.
   - Inside `runDiffGuard`, merge `config.allowedSymbolChanges` with the passed `allowedSymbolChanges` parameter internally, filtering out any empty/whitespace-only patterns.
   - Update `runASTDiffAnalysis` signature comparison matching to permit signature deletions/modifications if the signature matches any entry in `allowedSymbolChanges`.
   - The matching logic will use safe token boundaries (splitting signature by non-alphanumeric separators) and direct exact/substring comparisons to avoid dynamic `RegExp` syntax errors on special characters (e.g. parentheses).
8. **`src/cli/commands/run.ts`**:
   - Extract `contract.allowedSymbolChanges` and pass it to `runDiffGuard`.
9. **`src/safety/diff-guard.test.ts`**:
   - Add unit tests verifying `allowedSymbolChanges` works as expected, allowing specific symbol modifications/deletions that would otherwise be blocked by the AST diff guard.

## 2. Steps & Testing Strategy
1. Modify configuration schemas (`config.ts`, `session.ts`, `structured-schema.ts`, `json-response.ts`).
2. Implement symbol matching logic in `diff-guard.ts` and merge config-level allowed symbol changes.
3. Update `src/safety/diff-guard.test.ts`, `src/core/config.test.ts`, and `src/agents/json-response.test.ts` with test coverage.
4. Run `npm run build` to verify compilation.
5. Run `npm test` to verify all tests pass.
