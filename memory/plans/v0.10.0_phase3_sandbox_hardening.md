# Design Plan: Jewel v0.10.0 Phase 3 - Configurable Process Auditing & Sandbox Rules

We will implement Phase 3 of the Jewel v0.10.0 roadmap: **Configurable Process Auditing & Sandbox Rules**. This adds fine-grained Docker container isolation configuration for network isolation and filesystem mount policies, enabling high-integrity, sandboxed verification.

---

## 1. Affected Files

1. **`src/core/config.ts`**:
   - Add new properties to `JewelConfig` interface:
     - `sandboxNetwork?: 'none' | 'host' | 'bridge';` (determines container network configuration, defaulting to `'none'`)
     - `sandboxReadOnlyRoot?: boolean;` (makes the `/workspace` mount read-only, defaulting to `true`)
     - `sandboxWritePaths?: string[];` (specifies project-relative paths that should remain writeable via read-write mounts)
   - Update `DEFAULT_CONFIG` with defaults:
     - `sandboxNetwork: 'none'`
     - `sandboxReadOnlyRoot: true`
     - `sandboxWritePaths: []`
   - Update `validateAndMergeConfig()`:
     - Validate `sandboxNetwork` is either `'none'`, `'host'`, or `'bridge'`.
     - Validate `sandboxReadOnlyRoot` is a boolean.
     - Validate `sandboxWritePaths` is an array of strings.
     - **Security Validation & Normalization**: Reject absolute paths, paths containing colons (`:`), paths resolving to root (`.`, `./`, `""`), and parent traversals (checking `normalized === '..' || normalized.startsWith('../')` after converting backslashes to forward slashes to prevent cross-platform Unix/Windows traversal bypasses). Strip trailing slashes (unless the path is exactly `/`) to ensure canonical matching.
     - **Deduplication**: Normalize all paths first, and then deduplicate the normalized list using `Array.from(new Set(normalizedList))` to catch duplicates like `foo/bar` and `foo\\bar` (even with varying trailing slashes or backslashes). Return the deduplicated canonical normalized paths list.

2. **`src/verification/runner.ts`**:
   - Update `runVerification(config, cwd)`:
     - Apply `sandboxNetwork` policy: Append `--network`, `config.sandboxNetwork || 'none'` to `dockerArgs`.
     - Apply filesystem mount policies:
       - If `config.sandboxReadOnlyRoot` is `true`:
         - Mount the main workspace path as read-only: `-v`, `<host-cwd>:/workspace:ro`.
         - For each configured path in `config.sandboxWritePaths`:
           - Resolve its absolute path relative to the host `cwd`.
           - **Type Validation**: If the path exists on the host, verify it is a directory and not a file. Throw a descriptive error if it is a file.
           - Ensure the host directory exists (using `fs.mkdirSync` recursively) if it does not exist already.
           - **Symlink Escape Protection**: Resolve the real paths of the workspace (`cwd`) and the resolved write path (`absWritePath`) using `fs.realpathSync`. Wrap `fs.realpathSync(absWritePath)` in a `try/catch` block to handle permissions or resolution errors cleanly. Use `path.relative(realCwd, realWritePath)` to verify strict subdirectory containment. Normalize the relative path to forward slashes and verify it is not empty, does not equal `..`, and does not start with `../`, and is not absolute on the host, preventing host directory escapes.
           - Mount the path as read-write, normalizing container-side backslashes to forward slashes: `-v`, `<host-abs-path>:/workspace/<write-path-with-forward-slashes>:rw`.
       - If `config.sandboxReadOnlyRoot` is `false`:
         - Fall back to standard read-write mount for the workspace: `-v`, `<host-cwd>:/workspace` (no `:ro`).
     - **Argument Preservation**: Ensure all other existing docker parameters (user ID mapping, HOME environment setting, mounting the Jewel `dist` directory, setting process auditing environment variables/NODE_OPTIONS, user-defined `sandboxVolumes`, `sandboxEnv`, and the image/command arguments) are preserved and appended to `dockerArgs` in their correct order.

3. **`src/core/templates.ts`**:
   - Update `DEFAULT_CONFIG_CONTENT` to include the default values for the new properties:
     ```json
     "sandboxNetwork": "none",
     "sandboxReadOnlyRoot": true,
     "sandboxWritePaths": []
     ```

4. **`README.md`**:
   - Update the configuration snippet under `## Configuration: jewel.config.json` to include the default values for the new sandbox properties.

5. **`src/core/config.test.ts`**:
   - Add unit tests verifying validation of new configuration options:
     - Assert default values are set correctly.
     - Assert valid values (e.g. `sandboxNetwork: 'host'`, `sandboxWritePaths: ['coverage']`) pass validation.
     - Assert invalid values (e.g. invalid network type, non-boolean read-only option, non-array write paths) throw validation errors.
     - **Path Escape Tests**: Verify that absolute paths, paths containing colons (`:`), paths escaping the workspace (including backslash-based traversals), and root references (`.`, `./`, `""`) throw validation errors.
     - **Deduplication Test**: Assert that duplicate write paths (even with different trailing slashes and backslashes) are correctly deduplicated.
     - **Canonical Normalization Test**: Assert that returned write paths are canonically normalized.

6. **`src/verification/runner.test.ts`**:
   - Update the existing sandbox test `verification runner - sandbox docker execution and command assembly` to set `sandboxReadOnlyRoot: false` in its mock configuration to preserve its read-write workspace mounting assertion without regression.
   - Add new unit tests verifying:
     - `dockerArgs` contains `--network none` (or other config-defined networks).
     - `/workspace:ro` is mounted when `sandboxReadOnlyRoot` is `true`.
     - Configured `sandboxWritePaths` are mounted with `:rw` alongside the read-only workspace root, and container-side paths are normalized with forward slashes on Windows.
     - Symlink escape protection correctly throws an error when a write path resolves outside the workspace root (e.g., using `path.relative` check).
     - Traversal check handles folders starting with `..` (like `..coverage`) correctly as a valid subdirectory, and only blocks true parent escapes.
     - Type mismatch checking throws an error when a write path points to a file instead of a directory.
     - Filesystem paths are created on the host prior to execution.

## 2. Expected Changes

### Implementation Details

#### Interface & Validation in `src/core/config.ts`

```typescript
export interface JewelConfig {
  // ... existing fields ...
  sandboxNetwork?: 'none' | 'host' | 'bridge';
  sandboxReadOnlyRoot?: boolean;
  sandboxWritePaths?: string[];
}
```

Add parsing, validation, and deduplication rules in `validateAndMergeConfig`:
```typescript
  if (parsed.sandboxNetwork !== undefined) {
    if (!['none', 'host', 'bridge'].includes(parsed.sandboxNetwork)) {
      throw new Error('Invalid config: "sandboxNetwork" must be one of "none", "host", or "bridge".');
    }
    config.sandboxNetwork = parsed.sandboxNetwork;
  }

  if (parsed.sandboxReadOnlyRoot !== undefined) {
    if (typeof parsed.sandboxReadOnlyRoot !== 'boolean') {
      throw new Error('Invalid config: "sandboxReadOnlyRoot" must be a boolean.');
    }
    config.sandboxReadOnlyRoot = parsed.sandboxReadOnlyRoot;
  }

  if (parsed.sandboxWritePaths !== undefined) {
    if (!Array.isArray(parsed.sandboxWritePaths)) {
      throw new Error('Invalid config: "sandboxWritePaths" must be an array of strings.');
    }
    const normalizedList = parsed.sandboxWritePaths.map((item: any, i: number) => {
      if (typeof item !== 'string') {
        throw new Error(`Invalid config: "sandboxWritePaths[${i}]" must be a string.`);
      }
      
      // Block colons to prevent drive-relative escapes (e.g., C:foo) and NTFS Alternate Data Streams (ADS)
      if (item.includes(':')) {
        throw new Error(`Invalid config: "sandboxWritePaths[${i}]" contains a colon (":") which is not allowed.`);
      }

      // Convert backslashes to forward slashes before normalizing to ensure cross-platform consistency
      const posixPath = item.replace(/\\/g, '/');
      const isAbsolute = path.isAbsolute(item) || posixPath.startsWith('/');
      let normalized = path.normalize(posixPath).replace(/\\/g, '/');

      // Strip trailing slashes unless path is exactly /
      if (normalized.endsWith('/') && normalized !== '/') {
        normalized = normalized.slice(0, -1);
      }

      // Block root reference escapes, empty paths, and parent traversals
      const isRoot = normalized === '.' || normalized === './' || normalized === '';
      const isTraversal = normalized === '..' || normalized.startsWith('../');

      if (isAbsolute || isRoot || isTraversal) {
        throw new Error(`Invalid config: "sandboxWritePaths[${i}]" must be a relative path inside the workspace root and cannot escape it.`);
      }
      return normalized; // Return canonical normalized path
    });

    config.sandboxWritePaths = Array.from(new Set(normalizedList));
  }
```

#### Argument Assembly and Symlink Checks in `src/verification/runner.ts`

```typescript
          // Docker is available
          const dockerArgs = [
            'run',
            '--rm',
            '-i'
          ];

          // Mount workspace based on read-only setting
          const resolvedCwd = path.resolve(cwd).replace(/\\/g, '/');
          const realCwd = fs.realpathSync(cwd);

          if (config.sandboxReadOnlyRoot) {
            dockerArgs.push('-v', `${resolvedCwd}:/workspace:ro`);
            
            // Add read-write mounts
            if (config.sandboxWritePaths) {
              for (const wp of config.sandboxWritePaths) {
                const absWritePath = path.resolve(cwd, wp);
                
                // Verify type if host path exists
                if (fs.existsSync(absWritePath)) {
                  if (!fs.statSync(absWritePath).isDirectory()) {
                    throw new Error(`Invalid sandboxWritePath: "${wp}" exists on host but is a file, not a directory.`);
                  }
                } else {
                  // Host pre-creation of writable directory
                  try {
                    fs.mkdirSync(absWritePath, { recursive: true });
                  } catch {}
                }

                // Resolve realpath with user-friendly error wrapping
                let realWritePath: string;
                try {
                  realWritePath = fs.realpathSync(absWritePath);
                } catch (err: any) {
                  throw new Error(`Invalid sandboxWritePath: "${wp}" could not be resolved or created on the host. Error: ${err.message}`);
                }

                // Symlink escape validation via path.relative checks
                const relative = path.relative(realCwd, realWritePath);
                const normalizedRelative = relative.replace(/\\/g, '/');
                const isOutsideOrSame = normalizedRelative === '' || normalizedRelative === '..' || normalizedRelative.startsWith('../') || path.isAbsolute(relative);

                if (isOutsideOrSame) {
                  throw new Error(`Security Violation: sandboxWritePath "${wp}" resolves outside the workspace root.`);
                }

                const resolvedWritePath = absWritePath.replace(/\\/g, '/');
                const containerWritePath = wp.replace(/\\/g, '/');
                dockerArgs.push('-v', `${resolvedWritePath}:/workspace/${containerWritePath}:rw`);
              }
            }
          } else {
            dockerArgs.push('-v', `${resolvedCwd}:/workspace`);
          }

          dockerArgs.push('-w', '/workspace');

          // Network restriction configuration
          const net = config.sandboxNetwork || 'none';
          dockerArgs.push('--network', net);

          // ... subsequent existing arguments MUST be preserved:
          // user ID mapping, HOME environment setting, mounting the Jewel dist parent directory,
          // setting process auditing env variables/NODE_OPTIONS, user-defined sandboxVolumes,
          // sandboxEnv, and the image/command arguments.
```

## 3. Testing and Verification Strategy

1. **Unit Tests**:
   - `src/core/config.test.ts` to assert that the configuration properties are loaded and validated correctly, including negative test cases for absolute/traversal/colon paths.
   - `src/verification/runner.test.ts` to assert that the docker CLI command is constructed with the appropriate volume mounting tags (`:ro` and `:rw`), forward slash normalization, and `--network` values.
2. **Project Testing**:
   - Run `npm run build` to verify compilation.
   - Run `npm test` to verify all existing and new unit tests run and pass without regressions.
