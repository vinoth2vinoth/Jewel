# Design Plan: Jewel v0.9.0 Phase 1 - Critic Test Fixes

This plan addresses the hanging/infinite loop behavior in the `runTask` integration tests (`src/cli/commands/run-critic-retry.test.ts` and `src/cli/commands/run.test.ts`).

---

## 1. Problem Description

With the introduction of Multi-Agent Critic Reviews in Phase 1, the CLI's `runTask` now runs parallel LLM critic reviews (`runMultiAgentCriticReview`) on the generated patch diffs.
The tests in `src/cli/commands/run-critic-retry.test.ts` and `src/cli/commands/run.test.ts` intercept API requests using a mocked `globalThis.fetch`.
However, these mock fetch interceptors only look for:
1. `TaskContract` (to return a planning contract)
2. `TestCriticResult` (to return a test execution/correctness verdict)

Any other request falls through to returning a `PatchProposal`.
Because the LLM critic reviews (which request a `ReviewResult`) do not contain `TaskContract` or `TestCriticResult`, they receive a mock `PatchProposal` instead.
The parser in `reviewDiff()` for each adapter throws an error when validating this response against the `ReviewResult` schema.
The CLI catches the error, downgrades the critic status to `WARN`, and reports the failure.
However, because the critic status is not `PASS`, the CLI's verification loop does not break, leading to infinite retries in interactive mock tests or failing runs (exit code 1) in non-interactive tests.

---

## 2. Solution / Proposed Changes

Modify the mocked `fetch` implementations in both:
- `src/cli/commands/run-critic-retry.test.ts`
- `src/cli/commands/run.test.ts`

We will add a condition to intercept requests whose prompt or system message contains the word `ReviewResult` (or matches a critic type) and return a valid mock `ReviewResult` with `status: 'PASS'`.
Since the provider integrations in `run.test.ts` test multiple adapters, we must return the provider-specific JSON response payloads:

### OpenAI / OpenRouter Mock Response:
```typescript
      } else if (lastMessage.includes('ReviewResult')) {
        return {
          ok: true,
          json: async () => ({
            choices: [{
              message: {
                content: JSON.stringify({
                  status: 'PASS',
                  findings: ['Mock review passed.']
                })
              }
            }]
          })
        };
```

### Gemini Mock Response:
```typescript
      } else if (lastMessage.includes('ReviewResult')) {
        return {
          ok: true,
          json: async () => ({
            candidates: [{
              content: {
                parts: [{
                  text: JSON.stringify({
                    status: 'PASS',
                    findings: ['Mock Gemini review passed.']
                  })
                }]
              }
            }]
          })
        };
```

### Anthropic Mock Response:
```typescript
    } else if (body.system && (body.system.includes('critic') || body.system.includes('auditor') || body.system.includes('architect'))) {
      return {
        ok: true,
        json: async () => ({
          content: [{
            type: 'text',
            text: JSON.stringify({
              status: 'PASS',
              findings: ['Mock Anthropic review passed.']
            })
          }]
        })
      };
```

## 3. Affected Files

1. **`src/cli/commands/run-critic-retry.test.ts`**:
   - Update `globalThis.fetch` mocks in all tests to handle `ReviewResult` prompts correctly.

2. **`src/cli/commands/run.test.ts`**:
   - Update `globalThis.fetch` mocks in OpenAI, Gemini, Anthropic, and OpenRouter tests to handle `ReviewResult` prompts or system prompts correctly.
