# Plan - Jewel v0.7: Public Release Readiness and Real Provider Dogfooding

This design plan outlines implementation steps for v0.7, focusing on mock model report metadata correction, npm package file lists, release verification checks, CI pipelines, manual validation scripts, leaked secrets audits, and better runtime failure messages.

## Affected Files
1. `src/cli/commands/run.ts` (Update report metadata generation for `provider: 'none'`)
2. `package.json` (Update `files` field to include `docs`)
3. `package-lock.json` (Update for version bump)
4. `src/cli/commands/release-check.ts` (New: command performing release readiness assertions)
5. `src/cli/commands/release-check.test.ts` (New: unit tests for release-check command)
6. `src/safety/report-redaction-audit.ts` (New: scans reports for leaked secret keys)
7. `src/safety/report-redaction-audit.test.ts` (New: unit tests for leaked secrets scan)
8. `src/cli/index.ts` (Add `release-check` route, bump version to `0.7.0`)
9. `.github/workflows/ci.yml` (New: CI actions for matrix Node & OS builds)
10. `scripts/manual-real-provider-smoke.js` (New: script facilitating manual smoke runs)
11. `docs/manual-real-provider-validation.md` (New: step-by-step verification checklist)
12. `docs/model-capabilities.md` (New: document explaining model registry capabilities and fallback settings)

## Phase Details

### Phase 1: Fix Provider None Report Metadata
- Modify `src/cli/commands/run.ts` so that when `provider === 'none'`, the report lists:
  - Model: `"mock"` or `"N/A"`
  - Adapter name: `"mock-agent"`
  - Token usage: `"usage unavailable"`
  - Cost: `undefined` (unavailable)
- Add verification test assertions.

### Phase 2: Include Docs in NPM Package
- Edit `package.json` `"files"` to include `"docs"`.

### Phase 3: Public Release Checklist Command
- Create `src/cli/commands/release-check.ts` checking:
  - Version existence and format
  - `bin/jewel.js` and `dist` existence
  - `README.md` and `docs` presence
  - `"files"` containing `"bin"`, `"dist"`, `"docs"`
  - Leak detection via report-redaction-audit
  - `npm pack --dry-run` check
  - Executing command version/help check
- Add tests in `src/cli/commands/release-check.test.ts`.

### Phase 4: GitHub Actions CI Workflow
- Create `.github/workflows/ci.yml`. Configure push/PR builds on Ubuntu & Windows. Exclude live API calls.

### Phase 5: Real Provider Manual Validation Script
- Create `scripts/manual-real-provider-smoke.js`. Ensures `JEWEL_RUN_REAL_LLM_TESTS=true` and checks API keys before calling the smoke test command.

### Phase 6: Real Provider Dogfood Checklist
- Create `docs/manual-real-provider-validation.md` documenting manual global install and multi-provider dogfood steps.

### Phase 7: Report Redaction Audit
- Create `src/safety/report-redaction-audit.ts`. Iterates through reports and asserts `redactSecrets(content) === content`.
- Wire into `release-check` to warn on leaked secrets.

### Phase 8: Run Failure Clarity
- Refactor the main CLI error handlers to distinguish different failure types, printing user-friendly hints and suppressing standard stack traces on known user/adapter errors.

### Phase 9: Model Capabilities Documentation
- Create `docs/model-capabilities.md` detailing capability metrics.

### Phase 10: Version Bump
- Set version to `0.7.0` in `package.json` and `package-lock.json`.

### Phase 11: Final Verification
- Rebuild, run all tests, package dry run, and test dogfood broken project locally.
