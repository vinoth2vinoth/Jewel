# Design Plan: Jewel v0.9.0 Release Prep

Prepare the codebase for the official v0.9.0 release.

## 1. Affected Files
1. **`package.json`**: Update version string to `0.9.0`.
2. **`package-lock.json`**: Update version string in package descriptors to `0.9.0`. (Note: Since we are updating the harness source code directly via the coding assistant tools rather than running a nested `jewel run` task on ourselves, this will bypass the active Jewel policy protection on lockfiles).
3. **`src/cli/commands/release-check.ts`**: Update target warning target check to `0.9.0`.
4. **`src/cli/commands/release-check.test.ts`**: Update mock workspaces and test assertions to target version `0.9.0`.
5. **`CHANGELOG.md`**: Add `## [0.9.0] - 2026-06-05` section detailing the new milestone features (Multi-Agent collaboration, AST-Based Semantic Diff Guard, Isolated Sandbox Verification Runner, Local Web UI Dashboard).
6. **`README.md`**: Update hardcoded version references and installation tags from `0.8.0` to `0.9.0`.
7. **`docs/gemini-openrouter-validation.md`**: Update hardcoded version references from `0.8.0` to `0.9.0`.
8. **`docs/manual-real-provider-validation.md`**: Update version references from `0.8.0` to `0.9.0`.
9. **`docs/vinoth-real-provider-checklist.md`**: Update version references from `0.8.0` to `0.9.0`.

## 2. Steps & Testing Strategy
1. Modify `version` key in `package.json` to `"0.9.0"`.
2. Update the target warning check in `src/cli/commands/release-check.ts` (lines 31-35) to assert that version is not below target `0.9.0`.
3. Update `src/cli/commands/release-check.test.ts` to assert against target version `0.9.0` (changing `'0.8.0'` test setups to `'0.9.0'`).
4. Update `package-lock.json` version field to `"0.9.0"`.
5. Update `CHANGELOG.md` to add `## [0.9.0] - 2026-06-05` release notes.
6. Update hardcoded version references in `README.md`, `docs/gemini-openrouter-validation.md`, `docs/manual-real-provider-validation.md`, and `docs/vinoth-real-provider-checklist.md` to `"0.9.0"`.
7. Run `npm run build` to compile the TypeScript files (so compiled files capture the new version info).
8. Run `npm test` to ensure all compiled tests in the test suite pass successfully (148 tests).
9. Run `node dist/cli/index.js release-check` to verify readiness (checking credentials leakage, file list packaging config, etc.).
10. Run `npm run verify:dogfood-fixture` to verify the local dogfood example initial state.
11. Commit the version bump changes.
