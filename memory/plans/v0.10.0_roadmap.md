# Design Plan: Jewel v0.10.0 Roadmap - Semantic Isolation, Critic Self-Correction, and Monorepo Support

This roadmap outlines the objectives and architecture for Project Jewel v0.10.0, enhancing security bounds, self-correction capabilities, and multi-workspace control.

---

## 1. Objectives & Features

### Phase 1: Semantic Symbol Isolation Guard
- **Objective**: Prevent AI agents from modifying public API boundaries, exported symbols, or critical class properties unless explicitly allowed.
- **Mechanism**:
  - Extend the AST comparison engine (`diff-guard`) to generate structural signature checksums for all exported functions, classes, and types.
  - Fail verification immediately if a non-approved export is modified, renamed, or deleted.
  - Support configuring `"allowedSymbolChanges"` in the task contract or `jewel.config.json`.

### Phase 2: Critic Self-Correction & Loop Hardening
- **Objective**: Enable the linter and test runners to automatically feed error logs back to the primary patch agent for self-correction.
- **Mechanism**:
  - When verification (`lint` or `test`) fails, extract precise compiler or test runner failure output.
  - Spawn a local "Corrector Critic" sub-agent that takes the diff, error logs, and original file contents to suggest a correction patch.
  - Automatically apply and re-verify up to `maxRetries` without failing the session early.

### Phase 3: Configurable Process Auditing & Sandbox Rules
- **Objective**: Harden the isolated test runners by enforcing stricter system policies during verification execution.
- **Mechanism**:
  - Support blocking outgoing network connections during test/build execution (e.g., preventing tests from making external HTTP calls or exfiltrating data).
  - Enforce filesystem boundaries restricting verification tools to read-only access on the root directory, permitting writes only to designated `coverage/` or `tmp/` folders.
  - Integrate with system-level policies (seccomp, apparmor, or custom Docker runtime options).

### Phase 4: Premium Dashboard Visual Enhancements
- **Objective**: Upgrade the local Web UI dashboard to provide interactive control and visualization of complex multi-agent reasoning.
- **Mechanism**:
  - Visual AST tree diff explorer: Highlight added, deleted, or modified nodes.
  - Interactive file selection: Permit users to manually check/uncheck proposed files to accept or discard individual file patches before committing.
  - Live cost tracking gauge showing session token metrics and dollar cost.

### Phase 5: Multi-Repo & Monorepo Support
- **Objective**: Extend Jewel's safety harness to handle workspaces spanning multiple Git repositories or nested monorepo packages.
- **Mechanism**:
  - Maintain nested git checkpoints and run atomic rollback commands across all submodules/subrepos concurrently.
  - Support package-level config resolution policies for workspaces with multiple `package.json` files.
