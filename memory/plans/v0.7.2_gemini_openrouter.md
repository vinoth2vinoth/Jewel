# Implementation Plan - Jewel v0.7.2

Implementation plan for Gemini and OpenRouter Real Provider Validation hardening.

## Affected Files
1. `src/cli/commands/provider-ready.ts` - Refactor to fulfill all report fields, missing key reports, redaction, and correct filename outputs (`provider-ready.md` & `provider-ready.json`).
2. `src/cli/commands/provider-ready.test.ts` - Add unit tests testing the new report fields, missing keys, and mocked responses.
3. `scripts/manual-real-provider-smoke.js` - Update manual script to focus on Gemini & OpenRouter and enforce env flags.
4. `docs/gemini-openrouter-validation.md` - Update validation guide for version `0.7.2` and PowerShell commands.
5. `docs/vinoth-real-provider-checklist.md` - Update checklist for `0.7.2` and PowerShell setup.
6. `docs/model-capabilities.md` - Update with OpenRouter capability tables and model guidance.
7. `src/agents/providers/openrouter-adapter.ts` - Ensure OpenRouter schema unsupported response is extremely clear and suggests alternatives.
8. `package.json` & `package-lock.json` - Bump version to `0.7.2`.

## Proposed Changes

### 1. Hardening `provider-ready` command (`src/cli/commands/provider-ready.ts`)
- Modify so that it does NOT exit early on missing API key. Instead, write a readiness report with `apiKeyPresent: false`, status `FAIL`, and next action steps.
- Ensure the output file names are `.jewel/reports/provider-ready.md` and `.jewel/reports/provider-ready.json`.
- Ensure report includes:
  - `provider`
  - `model`
  - `apiKeyPresent` (true/false)
  - `structuredOutputSupported` (true/false/unknown)
  - `smokeResult` ("PASS" / "FAIL")
  - `retryCount` (0, or from adapter if retried)
  - `usage` (if available)
  - `redactionStatus` ("COMPLIANT" / "FAILED")
  - `nextAction` (string describing next steps)
  - `timestamp`
- Apply `redactSecrets` to all string outputs.

### 2. Hardening OpenRouter Model Switch Message
- When schema is unsupported or fails, provide a clear suggestion of alternative models (e.g. `openai/gpt-4o-mini`, `anthropic/claude-3.5-sonnet`) and reference `docs/model-capabilities.md`.

### 3. Verification & CI
- Run `npm test` and verify tests.
- Pack dry run check.
- Dogfood fixture check.
