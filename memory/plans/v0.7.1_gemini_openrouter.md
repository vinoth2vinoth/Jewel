# Plan - Jewel v0.7.1: Gemini and OpenRouter Real Provider Validation

This plan details the implementation of Jewel v0.7.1, prioritizing Gemini and OpenRouter validation, configuring preferred providers, creating readiness command routines, updating checklists, and bumping the version to `0.7.1`.

## Affected Files
1. `src/core/config.ts` (Add `preferredProviders` configuration support)
2. `src/cli/commands/doctor.ts` (Show preferred providers, suppress unused provider key warnings)
3. `src/cli/commands/release-check.ts` (Skip OpenAI/Anthropic key warnings if not preferred)
4. `src/cli/commands/provider-ready.ts` (New command `provider-ready` to check provider readiness)
5. `src/cli/commands/provider-ready.test.ts` (New unit tests for `provider-ready` command)
6. `src/cli/index.ts` (Wire up `provider-ready` command route and update help menu)
7. `scripts/manual-real-provider-smoke.js` (Refocus script on Gemini/OpenRouter, mark others optional)
8. `docs/gemini-openrouter-validation.md` (New validation guide)
9. `docs/vinoth-real-provider-checklist.md` (New user checklist)
10. `package.json` & `package-lock.json` (Bump version to `0.7.1`)

## Implementation Details

### Phase 1: Provider Priority Mode
- Update configuration schema in `src/core/config.ts` to support optional `preferredProviders: string[]` (defaults to `[]` or all).
- Update `doctor.ts` to output the configured preferred providers and skip warning about missing API keys for non-preferred providers.
- Update `release-check.ts` so it doesn't warn about missing keys for OpenAI/Anthropic unless they are explicitly in `preferredProviders`.

### Phase 2 & 3: Gemini and OpenRouter Validation
- Verify `smoke-provider` command logic works cleanly for Gemini and OpenRouter.
- Implement helpful model suggestions for OpenRouter structured output schema rejections.
- Save validation reports to `.jewel/reports/provider-smoke.md` and `.json`.

### Phase 4: Gemini and OpenRouter Manual Validation Docs
- Create `docs/gemini-openrouter-validation.md` containing PowerShell-first validation commands, Troubleshooting tips, and rate limit recovery.

### Phase 5: Manual Real Provider Script updates
- Modify `scripts/manual-real-provider-smoke.js` to showcase Gemini/OpenRouter examples and state that OpenAI and Anthropic are optional/skipped by default.

### Phase 6: Gemini and OpenRouter Dogfood Readiness Command
- Implement new `provider-ready` command under `src/cli/commands/provider-ready.ts`.
- Wire `provider-ready` command in `src/cli/index.ts` and add unit tests under `src/cli/commands/provider-ready.test.ts`.

### Phase 7: OpenRouter Model Suggestions
- Ensure that if an OpenRouter model does not support schemas, a helpful message is logged listing suggested models (e.g. `openai/gpt-4o-mini`, `meta-llama/llama-3.3-70b-instruct`).
- Validate that `allowUnstructuredProviderFallback` remains disabled by default.

### Phase 8: User Checklist Doc
- Create `docs/vinoth-real-provider-checklist.md` detailing the exact user verification flow with expected outputs.

### Phase 9 & 10: Version Bump & Final Verification
- Bump versions to `0.7.1`.
- Run all tests and verify dogfood broken fixture is kept broken.
