# Design Plan: Jewel v0.9.0 - Multi-Agent Hardening, AST Diffs, and Isolated Verification

This design plan outlines the major roadmap objectives for the next version of Jewel (v0.9.0). It focuses on multi-agent feedback loops, advanced syntax-level diff safety, and isolated sandbox runtime verification.

---

## 1. Objectives & Features

### Phase 1: Multi-Agent Collaboration & Specialized Auditors
- **Objective**: Expand the LLM validation loop by spawning specialized sub-agents to audit patches before they are tested.
- **Mechanism**:
  - Support configuring multiple domain critics (e.g., `"security"`, `"linter"`, `"architect"`).
  - Run parallel critique processes that report individual green/red approvals.
  - Support programmatic resolution where the linter sub-agent automatically suggests fixes to the primary patch writer.

### Phase 2: AST-Based Semantic Diff Guard
- **Objective**: Replace simple line-by-line regex checks with full AST (Abstract Syntax Tree) comparison.
- **Mechanism**:
  - Parse the original and modified source files using language-specific parsers (e.g. `typescript`/`acorn` for JS/TS).
  - Verify that only approved node types are added, modified, or deleted (e.g. preventing the modification of core class structures while permitting additional helper functions).
  - Perform semantic dependency mapping to warn if a change modifies code referenced by critical/protected modules.

### Phase 3: Isolated Sandbox Verification Runner
- **Objective**: Isolate system environments during the execution of verification commands (`npm test`, `pytest`, etc.).
- **Mechanism**:
  - Support spawning the test runner inside a lightweight container (such as Docker, podman, or microVMs).
  - Mount only the necessary scoped directory in read-write, with all other system components mounted as read-only or completely hidden.
  - Capture container exit codes, output logs, and resource usage boundaries.

### Phase 4: Local Web UI Dashboard
- **Objective**: Provide a rich local visual interface to trace, monitor, and override Jewel runs.
- **Mechanism**:
  - Add a `--ui` flag to `jewel run`.
  - Start a local server serving a premium Web UI displaying the live token usage, cumulative API cost, file diffs, test logs, and interactive controls.

## 2. Configuration Schema Additions (`jewel.config.json`)

We will add the following options:
```json
{
  "useASTDiffGuard": true,
  "verificationSandbox": {
    "enabled": false,
    "provider": "docker",
    "image": "node:20-alpine"
  },
  "critics": ["security", "linter"],
  "enableDashboard": false
}
```
