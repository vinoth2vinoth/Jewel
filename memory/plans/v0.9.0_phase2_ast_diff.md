# Design Plan: Jewel v0.9.0 Phase 2 - AST-Based Semantic Diff Guard

This plan implements Phase 2 of the Jewel v0.9.0 roadmap: **AST-Based Semantic Diff Guard**. We replace simple line-by-line checks with syntax-level AST comparison for JavaScript/TypeScript files, and implement semantic dependency mapping to warn if modifications affect protected modules.

---

## 1. Affected Files

1. **`src/core/config.ts`**:
   - Add `useASTDiffGuard?: boolean` to `JewelConfig`.
   - Default `useASTDiffGuard` to `false` in `DEFAULT_CONFIG`.
   - Update `validateAndMergeConfig()` to validate that `parsed.useASTDiffGuard` is a boolean.

2. **`src/safety/diff-guard.ts`**:
   - Safely attempt to import `typescript` dynamically (using `require('typescript')`) inside a `try-catch` block. If `typescript` is not installed/available, log a note and fall back to standard line-by-line checks.
   - Implement `runASTDiffAnalysis()` to parse original and new file contents and compare top-level declarations (classes, class methods/properties, functions, interfaces, type aliases, enums, variables). Wrap parsing and signature extraction in `try-catch` blocks; if a syntax error or parser crash occurs, log a warning finding and fall back to standard line-by-line checks for that file.
   - If any existing declaration signature is deleted or renamed/modified, mark the diff as `BLOCK` with descriptive findings.
   - Enforce config toggle check: only run AST comparisons if `config.useASTDiffGuard` is `true`.
   - Implement a workspace file crawler to locate all protected files.
   - Calculate relative import path strings from each protected file to the modified file. Normalize all paths to use forward slashes (`/`), strip extensions, and prepend `./` for same-directory paths.
   - Check if a protected file imports the modified file by searching for the normalized relative path enclosed in quotes (`'`, `"`, or `` ` ``). Add a `WARN` finding if a reference is detected.
   - Integrate `runASTDiffAnalysis` into `runDiffGuard()`.

3. **`src/safety/diff-guard.test.ts`**:
   - Add unit tests validating:
     - Deleting an existing function signature blocks the diff when `useASTDiffGuard` is enabled.
     - Changing a function signature parameters/name blocks the diff.
     - Deleting a class method blocks the diff.
     - Adding a new top-level function or method is permitted (`PASS`).
     - Modifying only the implementation body of a function/method is permitted (`PASS`).
     - AST diff guard is skipped entirely if `useASTDiffGuard` is `false`.
     - Graceful fallback behavior occurs if `typescript` is simulated as missing or if file content contains syntax errors.
     - Semantic dependency warnings are added when a modified file is imported by a protected file, using cross-platform safe normalized quote matching.

---

## 2. Detailed Implementation Details

### A. AST Signature Extraction
We will traverse top-level statements of the parsed AST using `typescript`:
- **ClassDeclaration**: Signature `class <ClassName>`. Members:
  - **MethodDeclaration**: Signature `method <ClassName>.<MethodName>(<Param1>,...)`.
  - **PropertyDeclaration**: Signature `property <ClassName>.<PropertyName>`.
- **FunctionDeclaration**: Signature `function <FunctionName>(<Param1>,...)`.
- **InterfaceDeclaration**: Signature `interface <InterfaceName>`.
- **TypeAliasDeclaration**: Signature `type <TypeName>`.
- **EnumDeclaration**: Signature `enum <EnumName>`.
- **VariableStatement**: Signature `<var|let|const> <VariableName>` for each declaration.

### B. Semantic Dependency Reference Check
For each changed file `A`:
1. Find all files in the project workspace (excluding `.git`, `node_modules`, `dist`, `.jewel`).
2. Identify which of these are protected files using `isProtectedPath(file, config)`.
3. For each protected file `B`:
   - Compute the relative import path from `B`'s directory to `A`:
     `rel = path.relative(path.dirname(B), A)`.
   - Normalize Windows backslashes: `relNorm = rel.replace(/\\/g, '/')`.
   - Remove file extension: `relNorm = relNorm.replace(/\.[jt]sx?$/, '')`.
   - If path doesn't start with `.`, prepend `./`:
     `const relativeImport = relNorm.startsWith('.') ? relNorm : './' + relNorm;`
   - Check if `B`'s source code contains this import path enclosed in quotes:
     ```typescript
     const importPatterns = [
       `'${relativeImport}'`,
       `"${relativeImport}"`,
       `\`${relativeImport}\``
     ];
     const referenced = importPatterns.some(pat => bContent.includes(pat));
     ```
   - If referenced, add a `WARN` finding:
     `"AST Diff Guard: Modified file '${A}' is referenced by protected module '${B}'."`
