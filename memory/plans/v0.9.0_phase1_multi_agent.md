# Design Plan: Jewel v0.9.0 Phase 1 - Multi-Agent Critics & Config Integration

This plan implements Phase 1 of the Jewel v0.9.0 roadmap: **Multi-Agent Collaboration & Specialized Auditors**. We will add support for running multiple parallel LLM-based critics (auditors) with specialized domains (e.g., security, linter, architect) during the patch evaluation phase.

---

## 1. Affected Files

1. **`src/core/config.ts`**:
   - Add `critics?: ('security' | 'linter' | 'architect')[]` to `JewelConfig`.
   - Default `critics` to `["security"]` in `DEFAULT_CONFIG`.
   - Update `validateAndMergeConfig()` to validate that `parsed.critics` is a valid array containing only allowed string values (`'security' | 'linter' | 'architect'`).

2. **`src/agents/adapter.ts`**:
   - Add `criticType?: 'security' | 'linter' | 'architect'` to the `ReviewInput` interface.
   - Add `criticResult?: CriticResult` (or `criticFindings?: string[]`) to the `PatchInput` interface.
   - Update `MockAgentAdapter` to mock responses for specialized diff reviews and support the updated interfaces.

3. **`src/agents/prompt-builder.ts`**:
   - Update `buildDiffReviewPrompt` to accept `criticType` and inject specialized domain instructions into the user prompt.
   - Update `buildPatchProposalPrompt` to format and include previous `criticResult` findings (e.g., security, linter, and architect remarks) in the context when proposing a patch during retries.

4. **`src/agents/providers/openai-adapter.ts`**, **`src/agents/providers/anthropic-adapter.ts`**, **`src/agents/providers/gemini-adapter.ts`**, **`src/agents/providers/openrouter-adapter.ts`**:
   - Update `reviewDiff()` to dynamically set the `systemPrompt` based on the `criticType` passed in `ReviewInput`.

5. **`src/safety/critic.ts`**:
   - Export a new async function `runMultiAgentCriticReview()` that:
     - Accepts `diffContent: string` as a parameter.
     - Calls the existing `runCriticReview` internally first to gather local heuristic status/findings.
     - Spawns parallel LLM-based reviews (`Promise.all`) using `adapter.reviewDiff()` for each critic in `config.critics`.
     - Handles errors from individual `adapter.reviewDiff` calls by catching them, converting them to a `WARN` status, and logging a warning finding (preventing a single network/timeout error from crashing the entire process).
     - Aggregates all LLM verdicts, findings, and required actions.
     - Merges them using strict status precedence: `BLOCK` > `WARN` > `PASS`.
     - Returns the aggregated `CriticResult`.

6. **`src/cli/commands/run.ts`**:
   - Update the validation loop to extract the raw `diffContent` (using git/backups) and call `await runMultiAgentCriticReview(..., diffContent)` instead of only `runCriticReview()`.
   - Pass the aggregated `critic` results to `adapter.proposePatch` on subsequent auto-fix retries.

## 2. Detailed Implementation

### A. Configuration Schema Validation (`src/core/config.ts`)
```typescript
if (parsed.critics !== undefined) {
  if (!Array.isArray(parsed.critics)) {
    throw new Error('Invalid config: "critics" must be an array.');
  }
  config.critics = parsed.critics.map((c: any, i: number) => {
    if (typeof c !== 'string' || !['security', 'linter', 'architect'].includes(c)) {
      throw new Error(`Invalid config: "critics[${i}]" must be one of "security", "linter", or "architect".`);
    }
    return c as 'security' | 'linter' | 'architect';
  });
}
```

### B. Dynamic Prompts in Adapters (`src/agents/prompt-builder.ts` & Provider Adapters)
We will map each critic type to a specific system persona/instruction:
- **`security`**: "You are an elite software security auditor. Review the proposed diff for credential exposure, shell injection, path traversal, unsafe dependency usage, or memory leaks."
- **`linter`**: "You are a code quality and linting auditor. Review the proposed diff for syntax errors, typing discrepancies, code formatting issues, and dead code."
- **`architect`**: "You are a software architect. Review the proposed diff for pattern compliance, file organization, coupling, scalability, and code readability."

Adapters will format the system prompt dynamically:
```typescript
const criticSystemPrompts = {
  security: "You are an elite software security auditor. You must return only a valid JSON object adhering to the ReviewResult schema.",
  linter: "You are a code quality and linting auditor. You must return only a valid JSON object adhering to the ReviewResult schema.",
  architect: "You are a software architect. You must return only a valid JSON object adhering to the ReviewResult schema."
};

const systemPrompt = criticSystemPrompts[input.criticType || 'security'];
```

### C. Heuristics & Parallel LLM Critic Merging (`src/safety/critic.ts`)
```typescript
export async function runMultiAgentCriticReview(
  contract: TaskContract,
  diffAnalysis: DiffAnalysis,
  verification: VerificationReport | null,
  config: JewelConfig,
  adapter: AgentAdapter | null,
  sessionPath: string,
  diffContent: string
): Promise<CriticResult> {
  // 1. Gather local heuristic check results
  const localResult = runCriticReview(contract, diffAnalysis, verification, config);
  
  if (!adapter || !config.critics || config.critics.length === 0) {
    return localResult;
  }

  // 2. Perform parallel LLM critic runs
  const llmPromises = config.critics.map(async (criticType) => {
    try {
      const reviewInput: ReviewInput = {
        diff: diffContent,
        verificationResult: verification,
        taskContract: contract,
        config,
        sessionPath,
        criticType
      };
      const result = await adapter.reviewDiff(reviewInput);
      return { criticType, status: result.status, findings: result.findings, success: true };
    } catch (err: any) {
      // Catch individual critic errors to prevent loop crash
      return {
        criticType,
        status: 'WARN' as const,
        findings: [`Critic "${criticType}" failed to respond: ${err.message}`],
        success: false
      };
    }
  });

  const llmResults = await Promise.all(llmPromises);

  // 3. Aggregate results
  let mergedStatus = localResult.status;
  const mergedFindings = [...localResult.findings];
  const mergedActions = [...localResult.requiredActions];

  for (const r of llmResults) {
    // Merge findings
    if (r.findings && r.findings.length > 0) {
      mergedFindings.push(...r.findings.map(f => `[Critic: ${r.criticType}] ${f}`));
    }
    
    // Status precedence hierarchy: BLOCK > WARN > PASS
    if (r.status === 'BLOCK') {
      mergedStatus = 'BLOCK';
      mergedActions.push(`Address blocking findings from the "${r.criticType}" critic.`);
    } else if (r.status === 'WARN' && mergedStatus !== 'BLOCK') {
      mergedStatus = 'WARN';
    }
  }

  return {
    status: mergedStatus,
    findings: mergedFindings,
    requiredActions: mergedActions,
    confidence: localResult.confidence
  };
}
```

## 3. Testing & Verification Strategy

- **Unit Tests**:
  - Update `src/safety/critic.test.ts` to verify `runMultiAgentCriticReview()` aggregates multiple parallel critics using `MockAgentAdapter`.
  - Validate config loader constraints for the `critics` list in `src/core/config.test.ts`.
  - Confirm error safety when one of the parallel LLM calls fails.
- **E2E Integration Test**:
  - Run a task using the mock adapter with `critics: ["security", "linter"]` configured, asserting that the generated CLI reports capture both security and linter mock feedback.
