# Design Plan: Jewel v0.8.0 - Code Coverage, Process Auditing, Interactive Overrides, and Budget Guards

This design plan outlines the major feature increments for Jewel v0.8.0, focusing on test coverage verification, child-process safety monitoring, interactive CLI overrides, and strict API cost boundaries.

---

## 1. Objectives & Features

### Phase 1: Test Coverage Guard
- **Objective**: Ensure AI modifications do not decrease test coverage or fall below a specified coverage floor.
- **Mechanism**:
  - Support configuring a coverage tool command (e.g. `c8`, `nyc`, `jest --coverage`) and a path to the coverage report (JSON/LCOV).
  - Parse the coverage report in `src/verification/runner.ts` post-run.
  - Assert that line/branch/function coverage meets the threshold specified in `jewel.config.json` (e.g. `"minCoverage": 80`).
  - Block finalize if coverage checks fail with status `COVERAGE_THRESHOLD_VIOLATION`.

### Phase 2: Runtime Process Auditing
- **Objective**: Harden the verification runner by auditing child process executions during tests.
- **Mechanism**:
  - Implement a monkey-patch or wrapper around shell executions during verification command runs (or parse command strings aggressively).
  - Block executions of commands that attempt to touch protected files, perform unrequested network requests, or execute unapproved binaries (e.g., `curl`, `wget`, `ssh`).

### Phase 3: Interactive Override & Debug Loop
- **Objective**: Provide developers with interactive options when a verification check fails.
- **Mechanism**:
  - If a check fails (e.g., `EXISTING_TEST_MODIFIED` or `VERIFICATION_FAILED`), instead of immediately aborting or retrying, present an interactive CLI prompt:
    - `[r] Retry with custom hint` (allows developer to type a prompt hint for the LLM)
    - `[o] Override failure` (finalizes the run despite the warning/failure if the user approves it)
    - `[a] Abort and rollback`
  - Disable this in non-interactive/CI environments.

### Phase 4: Session Cost & Budget Guard
- **Objective**: Limit financial risk during runaway retry loops by tracking cost.
- **Mechanism**:
  - Track prompt and completion token usage for each LLM provider call.
  - Calculate cumulative cost using priced configurations in `src/agents/model-capabilities.ts`.
  - Block further API calls and exit with `BUDGET_EXCEEDED` if cumulative cost exceeds the configured threshold (e.g., `"maxSessionCost": 0.50`).

---

## 2. Configuration Schema Additions (`jewel.config.json`)

We will add the following parameters:
```json
{
  "minCoverage": { "lines": 80, "branches": 75 },
  "coverageReportPath": "./coverage/coverage-summary.json",
  "maxSessionCost": 0.50,
  "auditSpawnedProcesses": true,
  "interactiveRetryMode": true
}
```

---

## 3. Affected Files

1. **`src/core/config.ts`**: Update configuration interface and defaults to support coverage, budget, process auditing, and interactive settings.
2. **`src/verification/runner.ts`**: Update to parse coverage reports and check minimum coverage thresholds.
3. **`src/verification/process-auditor.ts`** *(New)*: Implement shell command auditing and execution interception.
4. **`src/cli/commands/run.ts`**: Update the run loop to support interactive prompts on failure and enforce session cost limits.
5. **`src/agents/model-capabilities.ts`**: Add pricing metrics (input/output cost per 1k tokens) for each model.
6. **`src/agents/adapter.ts`**: Return model pricing/cost estimates alongside token usage.
7. **`memory/tasks/v0.8.0_roadmap.md`** *(New)*: Checklist of implementation actions.

---

## 4. Verification & Testing Strategy

- **Unit Tests**:
  - Test coverage parser with valid/invalid JSON summaries.
  - Test process auditor with allowed/blocked commands.
  - Test cost tracker accumulating charges and blocking above threshold.
- **E2E Tests**:
  - Mock interactive input in a test runner script to verify override and retry-with-hint actions.
