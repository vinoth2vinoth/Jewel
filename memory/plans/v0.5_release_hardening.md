# Plan - Jewel v0.5 Release Candidate Hardening and Real World Dogfooding

This plan outlines the design and implementation details to harden Jewel for real world dogfooding and release readiness.

## Affected Files
1. `src/cli/index.ts` (Add version command, update help, parse --dry-run option)
2. `src/cli/commands/version.ts` (New command to print version details)
3. `src/cli/commands/run.ts` (Add dry-run support, enrich MD/JSON reports with detailed execution stats, token usage, blocked reasons, etc.)
4. `src/cli/commands/version.test.ts` (New test file verifying `version` command)
5. `src/cli/commands/run.test.ts` (Add --dry-run tests)
6. `README.md` (Improve README positioning, add local install verification checklist/section)
7. `docs/windows-smoke-test.md` (New Windows PowerShell smoke test guide)
8. `docs/real-provider-dogfood.md` (New guide for safe real provider dogfooding)
9. `docs/release-checklist.md` (New release checklist document)

---

## Detailed Implementation Steps

### Phase 1: Local Install Verification
- Add a new section in `README.md` showing how to locally verify and install the package:
  ```bash
  npm pack
  npm install -g ./jewel-cli-0.4.0.tgz
  jewel --help
  jewel doctor
  jewel init
  jewel verify
  ```
- Detail exact commands to uninstall: `npm uninstall -g jewel-cli`.

### Phase 2: Windows PowerShell Smoke Test Guide
- Create `docs/windows-smoke-test.md` outlining the PowerShell commands for a complete smoke test. Ensure all syntax is compatible with Windows PowerShell (no UNIX-only commands like `rm -rf`, use `Remove-Item` instead).

### Phase 3: First Real Provider Dogfood Guide
- Create `docs/real-provider-dogfood.md` providing step-by-step instructions for safe testing of OpenAI, Gemini, Anthropic, and OpenRouter. Include warnings against running on production repositories directly, keeping human approval on, using target file scope (`--files`), and env var details.

### Phase 4: `jewel version` Command
- Create `src/cli/commands/version.ts` which reads the version from `package.json` dynamically and prints:
  - Package version
  - Node version
  - Platform / OS info
  - Default config path behavior
- Update `src/cli/index.ts` to recognize `version` command and update printHelp.
- Add `src/cli/commands/version.test.ts` to test the version output.

### Phase 5: Dry-Run Mode
- Add `--dry-run` to options in `src/cli/index.ts`.
- In `src/cli/commands/run.ts`, when `dryRun` is set to `true`:
  - Show the planned contract, provider, model, and allowed file scope.
  - Skip checkpointing, calling providers, modifying files, running verifications.
  - Report the output clearly and exit with `0`.
- Add test coverage in `src/cli/commands/run.test.ts` for the dry-run behavior.

### Phase 6: Improve Report Trustworthiness
- Modify `src/cli/commands/run.ts` report generation:
  - Include: Jewel version, Provider, Model, Adapter name, Verification commands run, Diff guard status, Safe patch writer status, Human review status, Rollback status, Changed files, Blocked proposed files.
  - Handle Token Usage properly. If not returned by the adapter, output `"usage unavailable"`.
  - Never invent or display hardcoded placeholder costs. Cost is only shown if it's truly known.
  - Make sure reports never output secrets.

### Phase 7: Improve README Positioning
- Refine `README.md` to state clearly what Jewel is (safety harness, provider-neutral, local-first, strict file scope) and what it is not (not a full Claude Code clone, not a replacement for git, not a blind run tool).

### Phase 8: Final Release Checklist
- Create `docs/release-checklist.md` detailing the step-by-step manual checks required before release.

### Phase 9: Verification
- Compile and run all tests, ensuring at least 72 tests pass.
- Verify the dogfood project locally in both broken and fixed states.
